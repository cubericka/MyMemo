# My Memo v3.4 변경 및 검증

## 전달 상태

요청한 기능의 소스 수정본입니다. APK는 생성하지 못했습니다. Android/Compose 전체 컴파일, Room/Robolectric 테스트, 실기기 테스트가 남아 있습니다. 기존 v3.3 APK를 v3.4로 이름만 바꿔 포함하지 않았습니다.

사용자가 이전 현재 확인 상태 항목을 모두 완료했다고 보고했습니다. 이는 기존 설치본의 검수 결과이며, 새 v3.4 기능의 검수 결과가 아닙니다. 고객 배포 검수는 요청에 따라 이번 작업 범위에서 제외했습니다.

## 사용 흐름

- 목록의 설정 탭 또는 톱니 메뉴 → 설정 → 전체 백업. Android 10 이상에서는 다운로드 폴더에 MyMemo_날짜_시간_구분값.bak를 생성합니다. Samsung 대상 기기는 이 경로를 사용합니다. Android 8~9에서는 시스템 저장 위치 선택창을 사용합니다.
- 전체 메모, 하위 관계, 체크리스트, 템플릿 상세, 고정·순서·날짜·휴지통·메모 잠금을 포함합니다. 기기의 위젯 인스턴스/런처 배치는 이식하지 않습니다. 기존 위젯은 복원된 메모 ID를 기준으로 갱신 요청을 받습니다.
- 잠긴 메모가 있으면 각 최상위 메모의 PIN 인증 후 백업합니다. 일반 메모는 평문이고 잠긴 메모 내용은 암호화 상태입니다. .bak 확장자 자체가 암호화를 의미하지 않습니다.
- 전체 복원 → .bak 파일 선택 → 잠긴 메모가 있으면 백업 당시 PIN 확인 → 현재 전체 메모/휴지통 교체 확인 → 복원. 병합·부분 복원 등 별도 옵션은 없습니다. 현재 잠긴 메모를 덮어쓰려면 현재 PIN도 확인합니다.
- 설정 → 메모 비밀번호 변경 → 대상 메모 선택 → 기존 PIN, 새 PIN, 새 PIN 확인. 4자리 숫자이며 메모 내용과 계층을 유지합니다. 잠금 상태에서 제목을 숨기므로 메모 ID를 함께 표시합니다. 기존 백업 파일의 PIN은 변경되지 않습니다.
- 기존 메모는 읽기 모드로 열립니다. 제목·본문·상세 항목을 읽고 복사할 수 있고 체크 상태를 변경할 수 없습니다. 하위 메모도 읽기 모드로 열립니다. 상단 수정으로 편집, 편집 중 읽기로 저장 후 읽기 복귀합니다. 새 메모는 바로 편집 모드입니다.

## 파일 형식과 데이터 보호

백업은 버전 1의 MyMemo.bak 논리 스냅샷 JSON입니다. 최대 64MB, 메모 10만/체크 50만 개로 제한합니다. 파일 형식·SHA-256 손상 검사, 중복 ID, 누락 부모, 순환/3단계 초과, 체크 소유 관계, 잠금 그룹 구조를 검증합니다. SHA-256은 우발적 손상 확인이며 공격자가 다시 계산할 수 있어 발신자 인증이 아닙니다.

잠금 메모 내용과 키의 PIN 암호화는 유지하고 원본 기기의 바깥 Keystore 래핑만 제거하여 내보냅니다. 복원할 기기의 키로 다시 감싸고, 각 PIN과 모든 보호 내용의 AES-GCM 검증이 성공한 뒤 DB를 한 트랜잭션에서 교체합니다. 원본 기기의 비밀키를 파일에 넣지 않습니다. 이 방식은 휴대폰 교체를 허용하지만 백업을 얻은 공격자는 기기 보호 없이 4자리 PIN을 추측할 수 있습니다. .bak를 비공개로 보관해야 합니다. 별도 백업 비밀번호 기능은 요청 범위상 추가하지 않았습니다.

MediaStore의 미완료 파일 상태를 이용해 쓰기 완료 후에만 파일을 공개하고 실패 시 해당 생성 파일을 정리합니다. 복원 실패 시 기존 DB를 유지하는 Room 트랜잭션을 사용합니다. 실제 Android 파일 공급자/Room 환경의 검증은 아직 필요합니다.

## 변경 파일

- BackupArchive.kt: 논리 스냅샷 직렬화, 파싱, 구조·손상 검증.
- BackupFiles.kt: 다운로드 저장, 제한 크기 읽기, 파일 실패 처리.
- NoteVault.kt: PIN 암호화 키의 기기 간 이동, 새 PIN 재래핑.
- Repository.kt: 전체 백업, 사전 검증 후 트랜잭션 복원, 기존 PIN 인증 후 변경.
- MainViewModel.kt: 백업/복원 흐름, PIN 요청, 읽기/편집 상태.
- SettingsScreen.kt: 설정 탭 화면, 전체 백업·복원·PIN 변경.
- ReadingScreen.kt: 입력·체크 조작 없는 읽기 화면.
- Screens.kt / PinDialog.kt: 화면 연결 및 PIN 안내.
- app/build.gradle.kts / AndroidManifest.xml: 버전 340, Debug는 .preview34 앱 ID와 ‘My Memo 3.4 테스트’ 이름으로 별도 설치되도록 구성. Release는 기존 앱 ID와 보호 설정 유지.
- 보호 도구: 검증 버전을 340으로 일치시킴.
- BackupTests.kt: Android/Room 테스트 5개 추가(실행 미완료).
- ScreenTests.kt: 재열기 기본 읽기 및 수정 전환 검수로 변경(실행 미완료).

## 이번에 실행한 검증

1. 실제 BackupArchive.kt, NoteVault.kt, Repository.kt, Templates.kt를 Kotlin/JVM으로 컴파일했습니다. Android Keystore API는 테스트 스텁, DAO/트랜잭션은 메모리 테스트 대역을 사용했습니다.
2. 핵심 로직 11개 통과: 잠금 내용 평문 미포함, 직렬화 왕복, 잘린 파일 거부, 다른 형식 거부, 잘못된 백업 PIN 거부, 서로 다른 기기 키에서 하위/체크/템플릿/휴지통 복원, PIN 변경 후 이전 PIN 거부 및 내용 보존, 잘못된 기존 PIN으로 변경 실패, 현재 잠금 미인증 덮어쓰기 거부, 순환 거부, 누락 부모 거부.
3. Kotlin 28개 소스/테스트 파일 구문 검사 오류 0. Android/Compose 타입 검사나 UI 실행 검증은 아닙니다.
4. 이전 v3.3의 36개 자동 테스트/10개 APK 검사 결과를 이번 버전의 통과 결과로 계산하지 않았습니다.

원본 결과 및 재현용 테스트 대역은 전달 ZIP의 verification/core에 있습니다. 이 테스트 대역은 앱 소스에 포함되지 않으며, Room의 실제 롤백·파일 I/O·Keystore·UI 검증을 대체하지 않습니다.

## 빌드 장애와 남은 작업

Gradle 8.13 및 JDK 17을 준비했지만 Gradle/SDK 관리자의 네트워크 연결이 거부되거나 도달 불가로 실패하여 AGP 8.13.2와 SDK/의존성을 해결하지 못했습니다. 오류 로그는 verification/build에 포함했습니다. 우회적으로 디버그 보호 해제를 Release에 적용하지 않았습니다.

Windows Android Studio에서 JDK 17/SDK 36/Build Tools 35.0.0을 준비하고 gradlew.bat testDebugUnitTest assembleDebug를 실행해야 합니다. Debug APK는 기존 앱과 분리되는 테스트용이며 기존 메모를 읽지 못합니다. 보호 무결성 실행이 생략되는 Debug를 배포용으로 사용하면 안 됩니다.

기존 v3.3 서명 개인키는 첨부 소스에 없으므로 동일 서명 업데이트 APK는 만들지 못했습니다. 개인키는 채팅에 첨부하지 말고 키 보유 환경에서 공식 빌드 안내에 따라 사용하세요. Release를 만들 때 기존 승인 인증서 지문을 제공하고 protect_release.py --version 340으로 처리해야 합니다. 다른 키로 만든 앱 설치를 위해 기존 앱을 삭제하지 마세요.

v3.4 실제 APK 생성 → Android/Compose 전체 빌드 및 Room/UI 테스트 → 다운로드 .bak와 다른 기기의 PIN 복원 → 동일 서명 업데이트 검증이 남아 있습니다. 신규 보호 APK fixture가 없으므로 InstalledIntegrityTests 10개는 생략되며, v3.3 fixture를 v3.4 테스트에 재사용하지 마세요.
