# My Memo 3.4.1 — 백업 제거와 수동 저장 수정

## 변경

- .bak 백업·복원 메뉴, 파일 선택, 직렬화, 키 이동 및 DB 교체 기능 제거.
- 저장 버튼: 입력 포커스를 정리하고 최신 초안을 저장. 다른 작업이 진행 중이면 기다려 처리하고, 동일 요청 연타는 합침.
- 저장 성공 후 ‘저장했습니다’ 하단 안내. 자동 저장이 이미 끝난 경우에도 안내.
- 저장 실패 시 성공 안내 없이 초안을 유지하고 오류 대화상자로 재시도 안내.
- 저장 후 편집 화면은 유지. 읽기 모드와 비밀번호 변경은 유지.
- DB 스키마·메모 ID·암호화 키 별칭·Debug 앱 ID(.preview34)는 변경하지 않음.
- versionCode 341, versionName 3.4.1-protected. 앱 표시는 ‘My Memo 3.4 테스트’를 유지.

## 원인 판단과 검증 한계

기존 저장 버튼은 flush만 실행하여 자동 저장 완료 뒤에는 눈에 띄는 반응이 없었고, busy 상태에서 action이 요청을 반환하는 코드가 있었습니다. 저장과 뒤로 가기는 같은 saveNow를 사용했습니다. 이 두 경로를 개선했지만, 사용 기기에서 저장 실패 자체를 재현한 것은 아닙니다.

소스 수준 확인: 백업 호출 잔여 참조 없음, 저장 완료 안내 및 실패 분기, 앱 식별자/DB 동일성, ZIP 정상 여부를 확인했습니다. 화면 회귀 테스트 2개를 추가했습니다(자동 저장 이후 수동 저장 안내, busy 도중 수동 저장 요청 대기와 DB 반영). 기존 편집 저장 실패/재시도 테스트는 유지합니다.

이 환경에는 이전 빌드 도구와 의존성이 남아 있지 않고 다운로드 제한 이력이 있어 Android 빌드나 새 테스트 실행을 완료했다고 주장하지 않습니다. 새 APK는 이 ZIP에 없습니다. 이전 검증 보고서는 과거 기록이며 3.4.1의 통과 결과가 아닙니다.

## Windows 적용 및 빌드

1. 이 ZIP을 새 폴더에 압축 해제합니다. 기존 소스에 덮어쓰기만 하면 삭제한 백업 파일/테스트가 남을 수 있으므로 새 폴더를 사용하세요.
2. Android Studio → Open → 이 ZIP의 MyMemo 폴더를 엽니다.
3. 기존처럼 JVM 21로 동기화합니다. Gradle/SDK 업그레이드는 필요하지 않습니다.
4. Generate APK를 실행합니다. 결과: MyMemo/app/build/outputs/apk/debug/app-debug.apk.
5. 이전 테스트 APK를 만든 동일 Windows 계정/서명 환경에서 빌드하면 같은 Debug 키를 사용하므로 3.4 테스트 앱에 업데이트하는 경로입니다. 기존 앱을 먼저 삭제하지 마세요. 키가 달라 설치 오류가 나면 삭제하지 말고 오류를 확인하세요.
6. 설치 후 새 메모 입력 → 저장 → ‘저장했습니다’ 안내 → 앱 재실행 후 내용 유지 확인. 자동 저장을 기다린 뒤 저장 버튼을 눌러도 안내가 나오는지 확인합니다.

테스트 실행은 프로젝트 폴더의 터미널에서 .\gradlew.bat testDebugUnitTest로 할 수 있습니다. Release fixture가 없는 설치 무결성 테스트는 생략됩니다. 새 Release APK/고객 배포 검수는 범위 밖입니다.

백업 기능 제거는 휴대폰 다운로드 폴더에 이미 생성된 .bak 파일을 자동 삭제하지 않습니다. 휴지통에서 메모를 복원하는 기능도 유지합니다. 이 변경은 앱 데이터 초기화나 기존 메모 삭제를 수행하지 않습니다.
