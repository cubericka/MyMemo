# 현재 Windows 배포 절차

현재 버전은 3.4.2 / 342입니다. `WINDOWS_RELEASE.md`의 `tools/build_release.py` 절차를 사용하세요. 아래 키 이력 및 검증 기록은 과거 버전 설명입니다. 실제 Release/변조 테스트는 아직 수행하지 않았습니다.

# 오프라인 보호 빌드 및 배포

현재 v3.3은 v3.2 검증용 서명을 유지합니다. v3.0/v3.1과는 서명이 다릅니다.

## 공식 배포 전 남은 결정

현재 전달 APK는 검증용 인증서 `CN=My Memo validation ONLY`로 서명했습니다. 공식 고객 배포용 키를 대신 정한 것이 아닙니다.
검증용 키의 개인키·비밀번호는 프로젝트 밖에서만 사용했고 결과물에 포함하지 않았습니다. 해당 키로 고객 배포를 시작하지 마세요.

기존 v3.0/v3.1 프리뷰는 소스와 개발용 키를 함께 전달했으므로 그 키를 더 이상 고객용 신뢰 기준으로 사용하지 않습니다.
동일 앱 ID에 다른 키로 서명한 이번 검증본은 기존 앱 위에 설치되지 않습니다. 설치를 위해 기존 앱을 삭제하면 메모가 없어질 수 있습니다.

공식 고객 배포를 처음 시작한다면 본인이 관리하는 새로운 서명 키로 시작하세요. 이미 프리뷰에 데이터가 있다면 보호 적용과 별도로 데이터 내보내기·가져오기 또는 서명 전환을 설계해야 합니다. 이번 변경은 기존 DB를 건드리지 않지만, 서로 다른 서명 간 데이터 이전 기능을 새로 제공한 것은 아닙니다.

## 구성

Kotlin/Java + Jetpack Compose + Room + DataStore + Android App Widget. Flutter/Dart, React Native/JS, WebView 앱이 아닙니다.
AGP 8.13.2, Kotlin 2.1.20, Gradle 8.13, JDK 17, compile/target SDK 36, min SDK 26, Build Tools 35.0.0.

Release: R8 코드 최적화·난독화·미사용 코드 제거, 리소스 제거, 최적화된 리소스 축소를 활성화했습니다. 광범위한 자체 keep 규칙은 없습니다. Room/AndroidX 소비자 규칙은 그대로 사용합니다.
Debug는 개발용이며 보호를 우회합니다. 고객에게 Debug 또는 unsigned APK를 전달하면 안 됩니다.

## 공식 키 준비

소스 프로젝트 밖의 안전한 위치에 RSA 2048비트 이상(신규 생성 시 3072비트 이상 권장) PKCS12 키를 보관합니다. 현재 도구는 RSA 인증서를 지원합니다.
키와 비밀번호를 소스·Git·ZIP·APK·채팅에 넣지 마세요. 환경변수는 로컬 빌드/CI의 비밀값 관리 기능으로 주입합니다. 비밀번호를 명령행 인자로 넣는 방식은 사용하지 않습니다.
승인된 공개 인증서 SHA-256은 별도 검토해 고정합니다. 환경변수의 값이 임의로 바뀌지 않도록 배포 권한을 관리하세요.

필수 환경변수:

- JAVA_HOME: JDK 17 경로
- MYMEMO_RELEASE_CERT_SHA256: 승인된 인증서 SHA-256, 소문자 64자리(복수 승인 시 쉼표 구분)
- MYMEMO_STORE_PASSWORD: 외부 PKCS12 저장소/개인키 비밀번호(현재 도구는 둘을 같게 설정한 저장소 지원)

SHA-256은 공개키 자체가 아니라 X.509 인증서 DER 전체의 지문입니다. 공개 인증서 내보내기 또는 `keytool -list -v`로 확인합니다. 이 값은 비밀이 아닙니다.

## 빌드 순서

```sh
./gradlew clean assembleRelease
python3 tools/protect_release.py \
  --apk app/build/outputs/apk/release/app-release-unsigned.apk \
  --output /absolute/output/MyMemo-release.apk \
  --keystore /absolute/private/official-release.p12 \
  --alias release \
  --pin "$MYMEMO_RELEASE_CERT_SHA256" \
  --sdk /absolute/android-sdk \
  --app-id com.personal.memostarter --version 342
```

복수 pin을 허용한 빌드라면 `--pin`에는 이번 실제 서명 인증서 하나의 지문만 지정합니다.
Windows에서도 Python 3.10 이상·JDK 17·Android Build Tools가 필요합니다. 현재 protect_release.py는 Windows의 .exe와 apksigner.jar 실행을 지원합니다. Windows에서는 WINDOWS_RELEASE.md의 build_release.py 진입점을 사용하세요.

도구는 선택 키의 공개 인증서와 승인 지문, Release에 생성된 BuildConfig 정책, 패키지/버전을 비교합니다. 프로젝트 안에 있는 키 및 과거 프리뷰 키는 거부합니다.

1. R8와 리소스 축소까지 끝난 unsigned APK를 입력합니다.
2. APK의 모든 파일 엔트리(DEX 전체, 모든 ABI의 .so, Manifest, resources.arsc, res/*, 기타 assets/META-INF 포함)의 압축 해제된 바이트 SHA-256을 계산합니다.
3. 패키지명·버전 코드와 해시 목록을 `assets/integrity.index`에 기록합니다.
4. 목록의 원본 바이트를 서명 키로 SHA256withRSA 서명해 `assets/integrity.signature`에 넣습니다.
5. zipalign 16KB 정렬 후 APK v2/v3 서명을 적용합니다. v1/v4는 사용하지 않습니다(min SDK 26).
6. apksigner verify 및 zipalign 검사 후 실제 APK 변형 테스트와 실기기 검수를 수행합니다.

목록과 목록 서명 파일만 자기 해시에서 제외합니다. 목록은 인증서 공개키로 따로 검증되므로 공격자가 해시값만 새로 쓰면 실패합니다. 서명 블록/ZIP 정렬은 엔트리의 압축 해제된 내용 해시에 영향을 주지 않습니다.
APK 전체 파일 해시를 DEX에 넣거나, 이미 서명한 APK에 나중에 파일을 추가하는 절차는 사용하지 않습니다.

버전을 바꾸면 Gradle의 versionCode 및 보호 도구의 --version을 함께 바꿉니다. 보호 도구를 거치지 않은 unsigned APK는 배포하지 않습니다.
현재는 단일 APK 직접 배포만 지원합니다. 예기치 않은 split APK는 거부합니다.

## 인증서 갱신 및 키 교체

API 28+에서는 SigningInfo.apkContentsSigners의 현재 서명자를 검사하며 과거 이력에 승인된 인증서가 있다는 이유만으로 새 서명자를 승인하지 않습니다. API 26/27은 GET_SIGNATURES로 현재 서명자를 검사합니다. 다중 동시 서명자는 허용하지 않습니다.

- 정상 키 교체는 다음 키의 공개 인증서를 사전 검토하고, 승인된 현재/다음 지문을 명시한 정책으로 새 Release를 빌드하는 방식입니다.
- 지문 허용 목록 수정만으로 Android의 업데이트 서명 정책을 우회할 수 없습니다. APK Signature Scheme v3 lineage 생성·보관·고객 OS별 업데이트 검증이 별도로 필요합니다.
- 현재 `protect_release.py`는 lineage 전환을 자동 수행하지 않습니다. API 26/27은 v3 키 교체 이력을 지원하지 않으므로 같은 기존 키 유지 또는 별도 데이터 이전 계획이 필요합니다.
- 노출된 키를 계속 허용하면 그 키로 만든 변조본도 승인될 수 있습니다. 키 유출 시 공식 복구/업데이트 절차를 수립하고 이전 키 허용을 제거합니다.
- 오프라인 앱은 새 정책을 설치하기 전까지 키 폐기 사실을 알 수 없습니다. 즉시 원격 폐기·강제 업데이트는 보장하지 않습니다.

## 테스트 재현

기능 테스트: `./gradlew testDebugUnitTest`.
APK 기반 어댑터 테스트는 생성된 fixture가 없으면 명시적으로 생략됩니다. 전체 검증에서는 아래 fixture 경로 환경변수를 지정해야 합니다.

별도 임시 검증 키 두 개를 프로젝트 밖에 준비합니다. 실제 운영 개인키로 공격 변형 테스트를 하지 마세요.
`tools/test_apks.py`의 두 키 alias는 release를 사용하며, 두 비밀번호는 MYMEMO_STORE_PASSWORD / MYMEMO_UNTRUSTED_PASSWORD 환경변수로 전달합니다.

```sh
python3 tools/test_apks.py \
  --apk /absolute/output/validation-release.apk \
  --approved-key /absolute/private/validation.p12 \
  --untrusted-key /absolute/private/untrusted.p12 \
  --pin "$MYMEMO_RELEASE_CERT_SHA256" \
  --sdk /absolute/android-sdk --output /absolute/apk-fixtures
export MYMEMO_SECURITY_FIXTURES=/absolute/apk-fixtures
./gradlew testDebugUnitTest
```

테스트용 정상 APK는 위 승인 검증 키로 먼저 전체 빌드·보호 처리해야 합니다. 공식 운영 키로 빌드한 APK를 다른 검증 키로 바꿔서 정상본이라고 테스트하지 않습니다.
`tools/VerifyApk.java`는 Android SDK apksig와 앱에 사용된 동일 PackageIntegrity.java를 사용합니다.
최종 R8 DEX 자체를 가상머신/기기에서 실행한 검증과는 다릅니다. 공식 서명본의 실제 설치·저장·위젯·업데이트 검수는 배포 전에 수행해야 합니다.

## 고객에게 전달할 파일

최종 공식 APK와 설치 안내만 전달합니다. 소스·R8 mapping·검증용 변조 APK는 개발자 보관용입니다. mapping은 크래시 분석을 위해 배포 버전별 비공개 보관합니다.
