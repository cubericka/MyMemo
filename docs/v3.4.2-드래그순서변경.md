# My Memo 3.4.2 — 드래그로 메모 순서 변경

## 사용 방법
전체 메모 탭에서 메모 또는 오른쪽 점 모양 아이콘을 길게 누른 뒤, 원하는 메모 위로 이동하고 손을 떼세요. 이동 대상이 색으로 표시됩니다. 아래로 옮기면 대상 다음, 위로 옮기면 대상 앞에 놓입니다. 변경 성공 시 안내가 표시됩니다.

- 같은 상위 메모 아래에서만 순서를 바꿉니다. 하위 메모는 전체 메모 목록에서 상위 메모를 펼친 뒤 이동하세요.
- 고정 메모끼리, 일반 메모끼리 각각 순서를 바꿉니다.
- 화면 위·아래 가장자리로 끌면 자동 스크롤합니다.
- 대상이 없는 곳에서 놓거나 취소하면 변경하지 않습니다.
- 검색 결과, 고정 메모 탭, 최근 수정 탭에서는 드래그하지 않습니다. 기존 위로/아래로 이동 메뉴는 유지합니다.
- 메모 내용·날짜·계층·잠금 데이터는 유지하며 순서만 트랜잭션으로 저장합니다. 잠긴 메모 이동에는 기존 인증 절차가 적용됩니다.
- 3.4.1의 백업 기능 제거와 저장 성공 안내 수정도 포함합니다.

## Windows에서 APK 생성
1. ZIP을 새 폴더에 압축 해제하고 Android Studio에서 MyMemo 폴더를 엽니다.
2. Gradle Sync 완료 후 debug 빌드 변형에서 Generate APK를 실행합니다.
3. 생성 위치: MyMemo/app/build/outputs/apk/debug/app-debug.apk
4. 기존 앱을 빌드했던 같은 PC·Windows 계정의 서명키를 유지하면 업데이트 설치할 수 있습니다. 앱을 삭제하지 마세요. 서명이 다르면 업데이트 설치되지 않습니다.

패키지 접미사 .preview34와 앱 표시 이름 My Memo 3.4 테스트는 유지합니다. versionCode 342, versionName 3.4.2-protected입니다. release 빌드는 기존 인증서 설정 및 보호·서명 절차가 필요합니다.

## 검증 상태 및 한계
소스 연결, 버전, 데이터베이스 스키마 불변, 백업 기능 제거 유지 및 ZIP 내용의 정적 확인을 수행했습니다. 이번 환경에서는 Android 빌드 도구와 의존성을 준비하지 못해 APK 생성, 컴파일, 자동 테스트 실행, 휴대폰 드래그 동작은 확인하지 못했습니다. 이전 버전 검증 보고서는 이번 버전의 실행 검증을 의미하지 않습니다.

추가 테스트 소스: ReorderTests(이동 방향·경계·내용 보존), DatabaseTests.dragOrderPersistsAfterReopen(잘못된 이동 취소·재실행 후 순서 및 체크리스트 보존). 테스트 소스는 포함했지만 실행하지 않았습니다.

빌드 가능한 환경에서: gradlew.bat :app:testDebugUnitTest :app:assembleDebug

휴대폰 확인 항목:
- 메모를 첫 위치↔마지막 위치로 옮기고 앱 재실행 후 순서 유지
- 같은 부모의 하위 메모 재정렬 및 상위 메모 이동 후 내용 유지
- 고정/일반 경계, 다른 부모, 빈 공간에 놓을 때 잘못된 이동 방지
- 긴 목록 가장자리 자동 스크롤, 드래그 취소, 이동 중 메모가 열리지 않는지 확인
- 잠긴 메모 인증 후 이동, 저장 버튼 안내 및 기존 메모 내용 유지
